Simulator PC Setup — Session Monitor & Remote Shutdown

Each bay PC needs a one-time setup so the system can shut it down after sessions and show on-screen warnings. Do these steps signed in as the PC's ADMIN account.

STEP 1 — TWO WINDOWS ACCOUNTS (recommended)
Create an ADMIN account (e.g. "BayAdmin", administrator, strong password) and a PLAYER account (standard user) that signs in automatically at boot. The admin account is what this booking system uses to shut the PC down — enter its username and password in this bay's fields above. The player account is what customers see; lock it down as much as you like.

STEP 1B — MAKE IT SIGN ITSELF IN (unstaffed facilities: essential)
A power blip must never leave a dead bay at a login screen. Signed in as the PLAYER account: on Windows 11 first go to Settings > Accounts > Sign-in options and turn OFF “For improved security, only allow Windows Hello sign-in” (it hides the checkbox below), and remove any PIN. Then press Windows+R, run netplwiz, select the player account, UNTICK “Users must enter a user name and password”, OK, confirm the password. Restart to test: straight to the player desktop, monitor up on its own.
STEP 2 — ALLOW REMOTE SHUTDOWN (one-time, as admin)
Open PowerShell as administrator and run these three commands:

Enable-NetFirewallRule -DisplayGroup "Remote Shutdown"

netsh firewall set service RemoteAdmin enable

reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" /v LocalAccountTokenFilterPolicy /t REG_DWORD /d 1 /f

Also give this PC a fixed IP address (a DHCP reservation on your router is easiest) and enter that IP in this bay's "Simulator PC IP" field above. If the IP ever changes, shutdown silently stops working.

STEP 3 — INSTALL PYTHON (one-time per PC)
Download Python 3 from python.org/downloads. During install, CHECK the box that says "Add Python to PATH", then choose "Customize installation", Next, and tick "Install Python for all users" before Install. The player account runs the monitor, so Python must be there for every account, not only the admin (the README in the monitor's zip says the same).

STEP 4 — BUILD & INSTALL THE SESSION MONITOR
In each bay above, click Build Session Monitor. It downloads a zip made for that exact bay — the script, an installer, and a README, with your web address, QR codes, and logo already built in. Nothing to edit. Copy the zip to that bay's PC and unzip it. First remove any older auto-start of a bay watcher (Task Scheduler, the Startup folders, the Startup apps list in Windows Settings, launchers such as AutoStart), then right-click install-monitor.bat, choose "Run as administrator", and restart the PC. From then on the monitor starts whenever ANY account signs in - player included. During a session it shows nothing until the ending warning: there is no timer on screen. Build and install it again after changing your logo, the first hero photo, your domain, your business name or this bay's name - they are built into it.

TROUBLESHOOTING
Shutdown stopped working: the Windows password changed (update it above), the PC's IP changed (fix the reservation), or the firewall rule got disabled (re-run Step 2).
Warnings stopped appearing: a Windows Python update removed the libraries — on the PC run: py -m pip install requests Pillow then restart the PC.
Reserved screen stuck on: press Ctrl+Shift+F12 on that PC (staff override; it stays off until the next session).

Door Access Provider
Which system issues each booking's door code. RemoteLock uses one lock via their cloud; UniFi Access uses your own UniFi console and can open multiple doors; Home Assistant drives a Z-Wave lock on your own network (no cloud). Only the chosen provider is used.
On (the default): RemoteLock and Home Assistant codes are put on the lock an hour before the session, the lock is asked whether it holds the code, and the customer is texted at the timing above (15 minutes before, unless you change it). A RemoteLock code opens the door only from the "works BEFORE" minutes; a Home Assistant code works from when it is on the lock. UniFi makes its code at the lead or the text timing, whichever comes first. The code is taken off the lock at the "works AFTER" minutes. A booking made at the last minute gets its code checked each minute for up to five and texted the moment the lock confirms. A Home Assistant lock can confirm; RemoteLock and UniFi cannot report this yet, so they text at the timing above without waiting. Off: the code is created and texted together 15 minutes before, the way it always was.
Applies to every provider. Example: 15 before / 30 after (the defaults) means a 3:00-4:00 booking's code opens the door from 2:45 to 4:30.
How it works. Your Home Assistant (set up under Home Assistant on this tab) talks to a Z-Wave lock on your own network. Each booking gets its own code in one of the lock's code slots, the unit checks the lock actually holds it before the customer is texted, and the code is cleared after the session. No cloud account, no monthly fee. A standing backup code lives in a reserved slot and is texted beside a booking's code if the lock ever fails to take one.
Locks Home Assistant knows about. Refresh the list

Keep your own family or staff codes outside them - the low slots (1-9) are left for that, and the unit never reads or changes a slot outside its range. One booking uses one slot for the length of its session; twenty slots covers twenty overlapping sessions.

Backups
Four steps, top to bottom, in the order to do them. Buttons marked 🔒 ask for your authenticator code when the sensitive lock is on.

What a backup holds —

Everything that matters: bookings, members, money and history, your settings, every signed waiver and waiver document, your PDF pages, your logo and app icons. Site photos and video are left out — they are the only thing that can make a backup huge, and you have the originals. After a restore you re-upload them in Website; the restore tells you which ones.

Two other files leave this unit from other places and follow the same passphrase: the year archive (the Records card, below) and each quarter's signed waivers (the Waivers tab) — neither can be downloaded until a passphrase is set.

1. Backup passphrase —

A backup holds your customers' details and your Stripe, texting, email and door keys. With a passphrase set, every copy that leaves this unit — the SD card or USB stick, your computer, a download, a year or waiver archive — is encrypted with it, and restore asks for it. Until one is set, nothing leaves on its own: the SD card and USB copies and the off-site link stay off, and neither a year's records nor a quarter's signed waivers can be downloaded. Write it on the same card as your recovery codes: if it is lost, those copies cannot be opened by anyone, including us. The copies kept on this unit stay readable, so the device can never lock you out.

2. Where the nightly copy also goes

Every night at a full backup is written to this unit (14 kept). Tick the extra places it should also be copied to — each one is checked byte for byte and keeps 14 nights.

Set a passphrase in step 1 first — a copy on a card or stick someone can pull out is only ever made encrypted.

Turn on the private link, download the ready-made script for your computer, run it once to test, then install it with the one line at the top of the script. Every night your computer pulls the encrypted backup and keeps the newest 30. The link is a long private key — it lives only in that script.
